# Отчёт по тестированию уровней изоляции транзакций в PostgreSQL

## 1. Создание таблицы и первоначальная загрузка данных

**SQL‑команды:**
```sql
CREATE TABLE persons (
    id SERIAL,
    first_name TEXT,
    second_name TEXT
);

INSERT INTO persons (first_name, second_name) VALUES ('ivan', 'ivanov');
INSERT INTO persons (first_name, second_name) VALUES ('petr', 'petrov');
COMMIT;
```

**Результат выполнения:**
- Таблица `persons` создана.
- В таблицу добавлены 2 записи.
- Транзакция завершена (`COMMIT`).

## 2. Проверка уровня изоляции транзакций

**Команда:**
```sql
SHOW transaction_isolation;
```

**Результат:**
```
 transaction_isolation 
-----------------------
 read committed
(1 строка)
```

**Вывод:** текущий уровень изоляции — `READ COMMITTED`.

## 3. Тестирование уровня изоляции `READ COMMITTED`

### Шаг 1: Начало транзакций в обеих сессиях

**Команда:**
```sql
BEGIN;
```

**Результат:** транзакции начаты в обеих сессиях.

### Шаг 2: Добавление записи в первой сессии

**Команда (сессия 1):**
```sql
INSERT INTO persons (first_name, second_name) VALUES ('sergey', 'sergeev');
```

**Результат:** запись добавлена (но не закоммичена).

### Шаг 3: Выбор данных во второй сессии

**Команда (сессия 2):**
```sql
SELECT * FROM persons;
```

**Результат:**
```
 id | first_name | second_name 
----+------------+-------------
  1 | ivan       | ivanov
  2 | petr       | petrov
(2 строки)
```

**Анализ:** новая запись не видна, так как:
- транзакция в сессии 1 не завершена (`COMMIT` не выполнен);
- уровень изоляции `READ COMMITTED` позволяет видеть только закоммиченные данные.

### Шаг 4: Завершение транзакции в первой сессии

**Команда (сессия 1):**
```sql
COMMIT;
```

**Результат:** транзакция завершена, данные зафиксированы.

### Шаг 5: Повторный выбор данных во второй сессии

**Команда (сессия 2):**
```sql
SELECT * FROM persons;
```

**Результат:**
```
 id | first_name | second_name 
----+------------+-------------
  1 | ivan       | ivanov
  2 | petr       | petrov
  3 | sergey     | sergeev
(3 строки)
```

**Анализ:** новая запись видна, так как транзакция в сессии 1 была завершена (`COMMIT`), и данные стали доступны на уровне изоляции `READ COMMITTED`.

### Шаг 6: Завершение транзакции во второй сессии

**Команда (сессия 2):**
```sql
COMMIT;
```

**Результат:** транзакция завершена.

## 4. Тестирование уровня изоляции `REPEATABLE READ`

### Шаг 1: Установка уровня изоляции

**Команда (обе сессии):**
```sql
SET transaction_isolation TO 'repeatable read';
```

**Результат:** уровень изоляции изменён на `REPEATABLE READ`.

### Шаг 2: Добавление записи в первой сессии

**Команда (сессия 1):**
```sql
INSERT INTO persons (first_name, second_name) VALUES ('sveta', 'svetova');
```

**Результат:** запись добавлена (но не закоммичена).

### Шаг 3: Выбор данных во второй сессии

**Команда (сессия 2):**
```sql
SELECT * FROM persons;
```

**Результат:**
```
 id | first_name | second_name 
----+------------+-------------
  1 | ivan       | ivanov
  2 | petr       | petrov
  3 | sergey     | sergeev
(3 строки)
```

**Анализ:** новая запись не видна, так как:
- транзакция в сессии 1 не завершена;
- уровень изоляции `REPEATABLE READ` гарантирует, что внутри транзакции видны только данные, зафиксированные на момент её начала.

### Шаг 4: Завершение транзакции в первой сессии

**Команда (сессия 1):**
```sql
COMMIT;
```

**Результат:** транзакция завершена, данные зафиксированы.

### Шаг 5: Повторный выбор данных во второй сессии

**Команда (сессия 2):**
```sql
SELECT * FROM persons;
```

**Результат:**
```
 id | first_name | second_name 
----+------------+-------------
  1 | ivan       | ivanov
  2 | petr       | petrov
  3 | sergey     | sergeev
(3 строки)
```

**Анализ:** новая запись по‑прежнему не видна, так как уровень изоляции `REPEATABLE READ` не позволяет видеть изменения, внесённые после начала транзакции, даже если они были закоммичены.

### Шаг 6: Завершение транзакции во второй сессии

**Команда (сессия 2):**
```sql
COMMIT;
```

**Результат:** транзакция завершена.

### Шаг 7: Финальный выбор данных во второй сессии

**Команда (сессия 2):**
```sql
SELECT * FROM persons;
```

**Результат:**
```
 id | first_name | second_name 
----+------------+-------------
  1 | ivan       | ivanov
  2 | petr       | petrov
  3 | sergey     | sergeev
  4 | sveta      | svetova
(4 строки)
```

**Анализ:** новая запись видна, так как:
- предыдущая транзакция во второй сессии завершена;
- новая транзакция начинается с актуальным снимком данных, включая запись, добавленную и закоммиченную в сессии 1.

## Выводы

1. **Уровень изоляции `READ COMMITTED`:**
   - позволяет видеть только закоммиченные данные;
   - изменения, внесённые в других транзакциях, становятся видны после их завершения (`COMMIT`).

2. **Уровень изоляции `REPEATABLE READ`:**
   - гарантирует, что внутри транзакции видны только данные, зафиксированные на момент её начала;
   - изменения, внесённые другими транзакциями после начала текущей, не видны, даже если они были закоммичены;
   - новые данные становятся видны только после завершения текущей транзакции и начала новой.
