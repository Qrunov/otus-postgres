## Подготовка тестовых данных

Создана таблица с первичным ключом и текстовым полем:

```sql
CREATE TABLE test (
    id INT PRIMARY KEY,
    t  TEXT
);

INSERT INTO test (id)
SELECT generate_series(1, 100000);
```

Поле `t` заполнено псевдослучайными строками (MD5 от случайного значения):

```sql
UPDATE test SET t = md5(random()::text)::text;
```

Для демонстрации полнотекстового поиска в части строк символ `f` заменён на пробел, чтобы в `t` появились «слова», находимые лексером:

```sql
UPDATE test SET t = replace(t, 'f', ' ');
```

Итог: **100 000** строк, PK на `id`, данные в `t` пригодны для GIN и составных индексов.

## 1. Базовый индекс (B-tree, первичный ключ)

При `PRIMARY KEY` на `id` автоматически создаётся индекс `test_pkey` (метод **btree**).

### Запрос и план

```sql
EXPLAIN SELECT * FROM test WHERE id = 50001;
```

```text
                              QUERY PLAN
-----------------------------------------------------------------------
 Index Scan using test_pkey on test  (cost=0.41..8.43 rows=1 width=36)
   Index Cond: (id = 50001)
(2 строки)
```

Планировщик выбирает **Index Scan** по `test_pkey`: условие равенства по ключу индекса, ожидаемо одна строка, низкая стоимость.

### Комментарий к индексу

```sql
COMMENT ON INDEX test_pkey IS
'Первичный ключ (B-tree) на id: уникальность строк и быстрый поиск по точному значению id.';
```

## 2. Индекс для полнотекстового поиска (GIN)

Создан GIN-индекс по вектору `to_tsvector` для конфигурации `english`:

```sql
CREATE INDEX txt_idx ON test
    USING gin (to_tsvector('english', t));
```

### Пример поиска

```sql
SELECT * FROM test
WHERE to_tsvector('english', t) @@ to_tsquery('english', '100');
```

Найдено 5 строк (в тексте после `replace` встречается лексема, связанная с запросом `100`).

### План с использованием индекса

```sql
EXPLAIN (COSTS OFF)
SELECT * FROM test
WHERE to_tsvector('english', t) @@ to_tsquery('english', '100');
```

Ожидаемый план (при достаточной селективности и актуальной статистике):

```text
Bitmap Heap Scan on test
  Recheck Cond: (to_tsvector('english'::regconfig, t) @@ '''100'''::tsquery)
  ->  Bitmap Index Scan on txt_idx
        Index Cond: (to_tsvector('english'::regconfig, t) @@ '''100'''::tsquery)
```

**GIN** хранит записи для элементов `tsvector` и эффективен для оператора `@@`.

### Комментарий к индексу

```sql
COMMENT ON INDEX txt_idx IS
'GIN-индекс для полнотекстового поиска по полю t (конфигурация english, to_tsvector).';
```

## 3. Частичный индекс (partial index)

Индекс только для подмножества строк — `id` в диапазоне (1000; 5000):

```sql
CREATE INDEX idx_part ON test (id)
WHERE id > 1000 AND id < 5000;
```

### Запрос и план с использованием частичного индекса

```sql
EXPLAIN SELECT t FROM test WHERE id = 1040;
```

```text
                              QUERY PLAN
----------------------------------------------------------------------
 Index Scan using idx_part on test  (cost=0.28..8.30 rows=1 width=33)
   Index Cond: (id = 1040)
(2 строки)
```

Значение `1040` попадает в предикат индекса → **Index Scan** по `idx_part`, а не полный обход таблицы.

### Комментарии к индексу
```
COMMENT ON INDEX idx_part IS
'Частичный B-tree на id только для строк с 1000 < id < 5000: меньший размер индекса и быстрый поиск в этом диапазоне.';
```

## 4. Составной индекс на несколько полей (B-tree)

```sql
CREATE INDEX idx_comp ON test (id, t);
```

Составной индекс упорядочивает ключи сначала по `id`, затем по `t`. Эффективен, когда в `WHERE` есть равенство/диапазон по **ведущему** столбцу `id`, а затем условие по `t`.

### Пример: Index Only Scan по составному индексу

Сужение диапазона по `id` и точное совпадение по `t`:

```sql
EXPLAIN SELECT * FROM test
WHERE id > 10000 AND id < 12000
  AND t = '9c035674622b317de80c999bac3c 100';
```

```text
                                            QUERY PLAN
--------------------------------------------------------------------------------------------------
 Index Only Scan using idx_comp on test  (cost=0.42..93.75 rows=1 width=37)
   Index Cond: ((id > 10000) AND (id < 12000) AND (t = '9c035674622b317de80c999bac3c 100'::text))
(2 строки)
```

Условия попадают в **Index Cond** — чтение только индекса `idx_comp`.

### Комментарий к индексу

```sql
COMMENT ON INDEX idx_comp IS
'Составной B-tree (id, t): диапазоны и равенство по id, затем отбор по t; Index Only Scan при узком диапазоне id.';
```

## Выводы

- В работе применены типы индексов: **B-tree** (PK, составной, частичный), **GIN** (полнотекстовый поиск).
- Для отчёта по заданию приведены планы `EXPLAIN`, где индекс реально используется: `test_pkey`, `txt_idx` (FTS), `idx_part`, `idx_comp`.
- Понятно, что индекс создаётся под **конкретные** запросы: частичный — под диапазон ключей, GIN — под `@@`, составной — под связку `id` + `t` с узким диапазоном по ведущему столбцу.
- Анализ планов показал разницу между **Index Scan**, **Index Only Scan** и **Seq Scan** и роль предиката частичного индекса и порядка столбцов в составном индексе.
